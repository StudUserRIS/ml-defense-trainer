ТРЕНАЖЁР ЗАЩИТЫ ML-ЛАБОРАТОРНЫХ — ЗАПУСК И ПУБЛИКАЦИЯ

Что входит в проект

public/index.html — интерфейс тренажёра.
worker/index.js — Cloudflare Worker: безопасный серверный шлюз к Gemini, генерация и проверка вопросов, адаптивная логика.
migrations/0001_schema.sql — схема Cloudflare D1 для сессий, вопросов, попыток и статистики.
public/examples/lab4.R — приложенный пример кода ЛР 4 для кнопки «Подставить приложенный lab4.R».
wrangler.toml — конфигурация Worker и D1.

Архитектура

Один Cloudflare Worker отдаёт сайт из папки public и обслуживает API /api/*. Браузер никогда не получает Google API key. На первичном анализе Worker передаёт код, текст, PDF и графики в Gemini, получает структурированную карту лабораторной и сохраняет только карту работы, вопросы, рубрики и ответы в D1. Сырые прикреплённые PDF/изображения намеренно не складываются в D1.

1. Подготовка Cloudflare

Установите Node.js LTS, затем в папке проекта выполните:

npm install
npx wrangler login
npx wrangler d1 create ml-defense-trainer

Команда создания D1 выведет database_id. Замените строку REPLACE_WITH_D1_DATABASE_ID в wrangler.toml этим значением.

Примените схему в production:

npx wrangler d1 migrations apply ml-defense-trainer --remote

Для локального запуска сначала примените локальную схему:

npx wrangler d1 migrations apply ml-defense-trainer --local

2. Секреты Gemini

В Google AI Studio создайте ключ Gemini API. Не вставляйте его в HTML, JavaScript клиента, Git или wrangler.toml. Из корня проекта выполните:

npx wrangler secret put GEMINI_API_KEY
npx wrangler secret put RATE_LIMIT_SALT

Во второй команде укажите длинную случайную строку. RATE_LIMIT_SALT используется для ключа ограничения запросов и не должен быть публичным.

Для локальной разработки вручную создайте файл .dev.vars (он не должен попасть в Git):

GEMINI_API_KEY=ваш_ключ
RATE_LIMIT_SALT=длинная_случайная_строка

3. Модели

По умолчанию в wrangler.toml выбраны:

GEMINI_FAST_MODEL = gemini-3.8-flash
GEMINI_DEEP_MODEL = gemini-3.1-pro-preview

Flash используется в режиме «Сбалансированный»: он подходит для повседневной генерации вопросов и проверки ответов с разумной стоимостью. Pro включается пользователем в режиме «Строгий» и полезен для первого глубокого анализа большой методички, сложных графиков и спорной оценки ответа. Если модель переименуют, замените только соответствующую переменную в wrangler.toml на актуальный ID, доступный вашему ключу, и разверните Worker заново.

4. Локальная проверка

npx wrangler dev

Откройте адрес, который покажет Wrangler. Первая загрузка создаёт защищённую HttpOnly cookie с идентификатором учебной сессии. Не используйте файл index.html напрямую через file://: сайту нужен Worker и D1.

5. Публикация

npx wrangler deploy

Worker опубликует и API, и статический интерфейс из public. Если фронтенд обслуживается с отдельного домена, укажите его точный origin в ALLOWED_ORIGIN в wrangler.toml, например:

ALLOWED_ORIGIN = "https://trainer.example.ru"

Если сайт и Worker опубликованы одной командой, ALLOWED_ORIGIN можно оставить пустым. Затем снова выполните npx wrangler deploy.

6. Перед первой реальной работой

Откройте сайт, добавьте lab4.R кнопкой примера или вставкой кода, затем приложите методичку, реальный консольный вывод и графики. Запустите анализ и проверьте блоки «Требования и покрытие», «Что преподаватель может оспорить» и «Как прочитаны результаты и графики». Там должны быть явно отмечены отсутствующие результаты: система не должна выдумывать их.

7. Эксплуатационные ограничения

В один анализ можно передать максимум 12 файлов, суммарно до 9 МБ после подготовки. Одиночный PDF ограничен 8 МБ. Скриншоты автоматически уменьшаются до безопасного размера. Ответы, карта работы и вопросы хранятся в D1 до удаления пользователем через интерфейс. Сырые файлы не сохраняются сервером после запроса анализа.

Ключ Google AI необходимо ограничить в Google Cloud по проекту, включённому API и, при возможности, квотам. Cloudflare secret нельзя переносить в браузер. Для учебной группы с большим числом пользователей дополнительно подключите Cloudflare Turnstile и отдельную авторизацию: cookie-сессия этого стартового проекта предназначена для личного тренажёра, а не для многопользовательского кабинета.

8. Что проверяет система

Она строит карту требований, понятий, функций/блоков кода, результатов, графиков и методологических рисков. Затем формирует один открытый вопрос с рубрикой, где сумма критериев всегда равна 10. Эталонный ответ хранится только на Worker до первой проверки. После ответа пользователь видит баллы по критериям, точные пробелы, исправления, развёрнутый эталон и персональный следующий вопрос. Адаптивная статистика повышает приоритет непроверенных, слабых и важных тем.
